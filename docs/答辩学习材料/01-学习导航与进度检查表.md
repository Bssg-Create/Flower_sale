# 花卉销售管理系统：学习导航与进度检查表

## 1. 这套材料是做什么的

这套材料不是让你把所有源码背下来，也不是让你重新开发一遍系统。

它的目标是把当前已经封版的项目，翻译成零基础也能逐步理解的学习路线。学完以后，你应当能够：

- 用自己的话介绍系统，而不是照着论文念。
- 说清前端、后端、数据库分别负责什么。
- 从页面上的一个操作，找到它对应的 Vue、API、Controller、Service、Mapper 和数据库表。
- 讲清登录权限、普通订单、模拟支付、取消恢复库存、发货收货和 DIY 花束定制。
- 在答辩老师追问时，知道应该打开哪个文件、看哪个方法。
- 不泄露账号、密码、Token、JWT 密钥或数据库凭据。

准确的项目架构表述是：

> 系统采用 Vue 3 + Vite 与 Spring Boot 的前后端分离开发方式，通过 REST API 通信；部署时将前端构建产物集成到 Spring Boot，实现单 JAR、单端口运行。

## 2. 最适合你的学习方法

每次只学习一小段，按照下面四步循环：

1. **先操作页面**：先知道用户做了什么。
2. **再画路线**：把页面到数据库的路线画出来。
3. **最后看源码**：只看这条路线涉及的文件和方法。
4. **用自己的话复述**：不看材料讲一遍，讲不清的地方再回看。

可以把项目想成一家鲜花店：

- Vue 页面是顾客看到的店面。
- Axios 是替页面跑腿送单据的店员。
- Controller 是前台接待。
- Service 是决定业务规则的店长。
- Mapper 是去仓库账本读写数据的人。
- MySQL 是仓库和账本。

第一次不需要理解每行代码。先记住“谁负责什么”，再逐步理解“它是怎么做的”。

## 7. 第一阶段口头验收题

不看材料，尝试回答：

1. 这个项目采用什么架构？
2. 四个后端模块分别负责什么？
3. 为什么运行 `FlowerApplication` 可以在 `8081` 打开完整页面？
4. `5173` 和 `8081` 有什么区别？
5. npm、Vite、Vue 分别是什么？
6. 为什么答辩时一般不需要运行 npm？
7. 如果老师问“系统最有特色的功能是什么”，应该重点介绍什么？

通过标准：

- 七道题至少能独立回答五道。
- 每道题不用背定义，能用自己的话说清即可。
- 回答中不出现真实账号、密码或其他敏感信息。

## 8. 建议的每周学习节奏

每周安排 3 次，每次 40～60 分钟即可：

- 第一次：阅读材料并在 IDEA 中找到对应文件。
- 第二次：不看材料画结构图或调用路线。
- 第三次：模拟老师提问，用手机录一段 3～5 分钟讲解。

如果讲不清，不代表不会编程，只说明这一小节还需要再重复一次。

## 9. 学习边界

现阶段不做以下事情：

- 不重构项目。
- 不合并 Maven 模块。
- 不恢复已经回退的设计。
- 不接入真实支付。
- 不把 AI 助手夸大成核心功能。
- 不要求记住全部类名和全部源码。
- 不读取或记录本机敏感环境文件内容。

当前最重要的目标是：**能够准确讲清已经实现的系统，而不是继续增加系统复杂度。**
